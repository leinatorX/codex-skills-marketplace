# 内容填充规范

本文件用于约束 PPT 每页的内容质量。生成页面时必须参考本文件，不能只看版式结构。

## 标题规则：标签 → 结论

页面标题必须写成**判断句或行动句**，不能是孤立名词标签。

### 标题对照表

| ❌ 标签式（禁止） | ✅ 结论式（推荐） |
|---|---|
| 公司概况 | 安信是数智赋能的安全应急解决方案平台 |
| 核心能力 | 从仿真训练到实战指挥，覆盖安全应急全链条 |
| 产品矩阵 | 硬件感知 + AI 预警 + 仿真推演构成完整产品线 |
| 合作伙伴 | 已连接 47 家保司和 320 个园区形成服务网络 |
| 技术架构 | 三层架构实现从边缘感知到中心决策的秒级响应 |
| 解决方案 | 危化事故预防需要平台化协同而不是单点工具 |
| 行业背景 | 安责险保费规模破百亿，风险减量成刚需 |
| 问题与挑战 | 传统安全管理靠人盯人，无法应对复杂场景 |
| 案例展示 | 某石化园区上线 6 个月事故率下降 37% |
| 工作基础 | 3 年积累 127 个项目验证了平台化路径可行 |
| 推进计划 | 2025 年聚焦 3 个省份完成规模化复制 |
| 组织架构 | 专委会连接政府、保司、企业三方资源 |
| 市场分析 | 危化安全市场年增速 18%，政策窗口已打开 |
| 总结展望 | 从单点项目到平台服务，安信已准备好规模化 |
| 数据分析 | 能源业务收入 127.7 亿美元，同比增长 27% |

### 标题自检

写完标题后问自己：

1. 这个标题是否传达了一个**判断**？——"安信覆盖了全链条"是判断，"核心能力"不是。
2. 听众看完标题后是否知道**这页在说什么结论**？
3. 是否可以在标题前加"我认为"变成一句完整的话？

## 卡片内容三要素

每个卡片至少包含 **对象 + 事实/数字 + 含义** 三个要素。

### 反面示范（禁止）

```html
<div class="card">
  <h3>虚拟仿真</h3>
  <p class="desc">提升安全培训效果，赋能应急能力建设</p>
</div>
```

问题：没有对象范围、没有数字、"赋能"是空词。

### 正面示范（推荐）

```html
<div class="card">
  <div class="num">47</div>
  <h3>虚拟仿真训练系统</h3>
  <p class="desc">覆盖危化、消防、地震 3 大场景，已部署 47 个园区，年训练超 12 万人次</p>
</div>
```

### 更多正面示范

```html
<!-- metrics 版式的数字卡片 -->
<div class="card">
  <div class="num">127.7亿</div>
  <h3>能源业务年收入</h3>
  <p class="desc">同比增长 27%，是全年最明确的增长引擎</p>
</div>

<!-- problem 版式的问题卡片 -->
<div class="card">
  <h3>预案与实战脱节</h3>
  <p class="desc">82% 的危化企业预案超过 2 年未更新，演练流于形式，实际事故中无法指导处置</p>
</div>

<!-- solution 版式的能力卡片 -->
<div class="card">
  <h3>AI 预警引擎</h3>
  <p class="desc">接入 IOT 传感器 + 气象数据，对可燃气体泄漏实现 90 秒预警，误报率低于 3%</p>
</div>
```

## 空泛词黑名单

以下词汇如果**没有具体对象和数据支撑**，禁止使用：

| 空泛词 | 问题 | 改写方向 |
|---|---|---|
| 赋能 | 没有说清赋能什么、怎么赋能 | 改为"为 XX 提供 YY 能力" |
| 闭环 | 没有说清环上有哪些节点 | 改为"从 A 到 B 到 C 的完整流程" |
| 全面提升 | 提升了什么、提升了多少 | 改为"XX 指标从 A 提升到 B" |
| 显著增强 | 增强了什么、证据是什么 | 改为具体案例或数字 |
| 打造平台 | 平台包含什么、服务谁 | 改为"整合 XX 和 YY 的服务平台" |
| 推动发展 | 推动什么发展、怎么衡量 | 改为具体行动和指标 |
| 高质量发展 | 太泛，无法验证 | 改为具体目标 |
| 深度融合 | 融合了什么、融合后怎样 | 改为"将 A 嵌入 B 的 C 环节" |
| 行业领先 | 领先什么、谁说的 | 改为客户数、排名或第三方评价 |
| 创新驱动 | 创新了什么 | 改为具体技术或产品 |

## 页面内容最低标准

| 版式 | 最少内容要求 |
|---|---|
| overview | 至少 3 个带数字的指标卡 + 1 段定位说明 |
| problem | 至少 3 个具体问题，每个问题有现状描述 |
| solution | 至少 4 个能力模块，每个有对象和动作 |
| metrics | 至少 3 个大数字，每个有单位和含义 |
| product-grid | 至少 4 个产品，每个有名称、类型和价值 |
| case-study | 至少 1 个客户名/场景 + 问题 + 方案 + 结果 |
| roadmap | 至少 3 个阶段，每阶段有时间和交付物 |
| closing | 至少 3 条具体结论或行动建议 |
| data-dashboard | 至少 3 个 KPI + 同比或环比 + 1 条判断 |
| chart-analysis | 至少 1 个图表 + 3 条发现 |
| financial-table | 至少 4 行数据 + 单位 + 变化方向 |
| risk-action | 至少 3 个风险 + 对应行动 |
| comparison | 至少 2 个对比对象 + 3 个对比维度 |

## 资料不足时的处理

如果用户给的材料不足以支撑具体内容：

1. **宁可减少页数**，不要用空泛词凑页。
2. **宁可缩小范围**，不要编造数据。
3. **明确标注**需要用户补充的位置：`[待补充：具体客户数据]`。
4. 不要用"行业领先""全面覆盖"等无法验证的判断填充。
