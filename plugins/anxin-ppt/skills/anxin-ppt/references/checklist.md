# 安信 PPT 交付检查清单

## 内容

- 是否先确定了受众、核心论点和叙事弧线。
- 目录页是否按“背景 -> 问题 -> 方案 -> 证明 -> 行动”组织，而不是按素材分类堆页。
- 每页标题是否像结论句，而不是“组织概况”“核心能力”这类孤立标签。
- 每页标题字号是否克制，是否避免了大屏海报式压迫感。
- 相邻两页之间是否有明确承接关系。
- 整体是否像一份完整 PPT，而不是 8 页网页式概要。
- 报表、工作总结、项目复盘类材料是否包含章节页、图表页、表格页和结论页。
- 除封面外，每页是否填写了 `data-question` 和 `data-message`。
- 第一页是否是全屏背景 + 中文大标题的简洁封面，且没有页码、说明段落、目录或底部导航点。
- 第二页是否是目录页。
- 页面标题是否全部中文优先。
- 是否避免了无意义英文小标题和中英混排。
- 每页只回答一个核心问题。
- 每页是否至少包含 3 个具体事实、数字、对象、动作或来源支撑。
- 标题是否是结论句（判断句或行动句），而不是"公司概况""核心能力"这类孤立标签。
- 每个卡片是否包含"对象 + 事实/数字 + 含义"三要素。
- 是否避免了“赋能、闭环、提升、强化、推动、打造、深度融合、行业领先”等空泛词堆砌。
- 数字是否来自用户材料或可核实来源。
- 是否没有编造客户、政策、数据和合作关系。
- 内容密度是否接近 `assets/example-full-deck.html` 的水平。

## 版式

- 每页 `<section class="slide">` 是否有 `data-layout`。
- `data-layout` 是否来自 `references/layouts.md`。
- 标题、正文、图片、页码是否没有重叠。
- 正文页是否没有使用内联超大字号覆盖模板默认层级。
- 页面是否保持蓝白企业汇报风，不像营销海报。
- 信息密度是否接近企业汇报：不能过度堆满，也不能只有大标题和空卡片。
- 是否使用了表格、图表、时间线、对比页等 PPT 常见表达，而不是全程重复卡片。
- HTML 结构是否从 `layouts.md` 的骨架复制，而不是临时发明。

## 图片

- 正式交付是否至少有封面主视觉或关键方案图。
- 图片是否放在 `images/` 目录。
- 图片路径是否真实存在。
- 图片内部是否没有页眉、页脚、页码、logo、水印。
- 图片中的文字是否为简体中文且可读；若无法保证文字准确，优先不让图片内含文字。

## 技术

- 运行 `scripts/validate-blue-deck.mjs` 是否通过。
- 浏览器打开是否能翻页。
- `Esc` 是否打开/关闭缩略图索引页，而不是返回首页。
- 缩略图索引页是否显示所有页面，点击缩略图是否能跳转到对应页。
- 首页、目录页、密集内容页是否截图检查过。
- 是否生成完整 zip 包，并确认 zip 内包含 `index.html` 和 `images/`。
- 本地文件没有泄露 API Key、客户敏感数据或未脱敏材料。
