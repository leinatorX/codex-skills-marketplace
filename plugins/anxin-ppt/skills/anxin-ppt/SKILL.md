# 安信企业汇报 PPT

## 这个 Skill 做什么

生成一份**蓝白企业汇报风 HTML PPT**，面向 OpenClaw 的技能配置和实际交付。

默认视觉基调：

- **蓝白配色**：白底、深蓝标题、浅蓝结构块、少量高亮蓝。
- **企业汇报**：稳重、清晰、可信，避免炫酷营销风、霓虹科技风和过度装饰。
- **字号克制**：面向企业汇报而不是发布会大屏，标题要有层级但不能压迫页面。
- **封面极简**：第一页默认使用全屏背景图 + 中文大标题，不放页码、目录、数据卡片、说明段落或复杂装饰。
- **第二页目录**：第二页固定为目录页，说明整份汇报结构。
- **中文优先**：页面标题、正文、图注、指标说明默认使用简体中文。
- **HTML 横向翻页**：单个 `index.html` 可直接浏览器打开演示。
- **可配图**：需要封面图、场景图、架构图、生态图时，优先调用同级 `anxin-image-gen`。
- **压缩包交付**：OpenClaw 通过飞书交流时，最终交付必须是包含 HTML、图片和资产的完整 zip 附件。
- **主线驱动**：先确定整份 PPT 的一句话论点，再生成页面；不要按素材分类机械堆页。
- **可预览**：生成后至少产出封面、目录和一页密集内容截图，便于在飞书中快速判断质量。
- **资料型汇报优先**：默认生成“完整企业汇报 PPT”，不是网页式大留白演示；年度报表、工作总结、项目复盘类材料必须有章节页、图表页、表格页和结论页。
- **PPT 式导航**：`Esc` 必须打开/关闭缩略图索引页，点击缩略图跳转到对应页面；不要把 `Esc` 绑定为返回首页。

## 强制交付规则

这些规则不是建议，生成时必须满足。任一项不满足，都要先修改 PPT，再交付给用户。

1. **封面必须有图**：第一页必须包含 `.cover-bg img`，图片来自本地 `images/` 目录；不得用纯色背景冒充封面图。
2. **封面只留标题**：第一页只保留中文大标题，不放副标题、公司信息、页码、底部导航点、说明段落或发起单位。
3. **第二页必须是目录**：第二页必须是 `data-layout="agenda"`，用中文列出 4-6 个汇报章节。
4. **一页只讲一个重点**：每页正文只保留关键结论，不把资料原文整段搬进页面。
5. **控制信息密度**：普通页面建议不超过 6 个内容块；如必须展示 8 项业务范围，要拆成两页或改成更轻的关键词矩阵。
6. **图表不能裁切关键内容**：流程图、架构图、生态图优先使用 `object-fit: contain`，不要用 `cover` 导致文字或底部被切掉。
7. **必须校验通过**：交付前必须运行 `validate-blue-deck.mjs`；失败时必须返工，不能解释后直接交付。
8. **必须打包 zip**：OpenClaw 通过飞书交付时，最终必须提供完整 zip 附件，不能只给 `index.html`。
9. **必须有叙事主线**：生成页面前必须写清楚“受众、核心论点、叙事弧线、每页承接关系”；页面顺序必须服务这条主线。
10. **字号不能过大**：不要为单页标题临时写超大 `font-size`；除封面外，正文页标题使用模板默认层级，避免占据页面上半屏。
11. **必须生成预览图**：正式交付前至少截图第 1 页、第 2 页和一页信息密度最高的正文页。
12. **不能空泛**：正文页不能只写“提升效率、强化能力、构建闭环、赋能发展”等抽象词；每页至少包含 3 个具体事实、数字、对象、动作或来源支撑。
13. **报表类必须有图表**：年度报表、财务分析、经营复盘类 PPT 必须包含指标看板、趋势/结构图、数据表、变化原因和后续关注点，不能只做观点卡片。
14. **Esc 是缩略图索引**：模板中底部提示应写 `Esc 缩略图`；键盘事件里 `Escape` 只切换缩略图索引，不执行 `go(0)`。
15. **图片比例必须匹配槽位**：`image-16x9` 必须使用 16:9 图片，`image-3x2` 必须使用 3:2 图片；如果只有 16:9 图，不要硬塞进 3:2 槽位。
16. **不要滥用“无文字/无 Logo”**：场景图可以要求无水印、无乱字；品牌封面、产品图、展台、设备图允许真实品牌标识或产品铭牌。不要一律要求“无 Logo”，也不要让模型生成伪造 Logo。
14. **标题必须是结论句**：每页标题必须是判断句或行动句，不能是"公司概况""核心能力"这类孤立标签。参考 `references/content-guide.md` 的标题对照表。
15. **必须参考示例**：生成前必须阅读 `assets/example-full-deck.html`，理解每页应有的内容密度和写法。
16. **卡片三要素**：每个卡片至少包含"对象 + 事实/数字 + 含义"三个要素，不能只写空泛价值词。参考 `references/content-guide.md`。

## 何时使用

适合：

- 公司介绍、业务概览、客户拜访材料
- 安全应急、危化、园区、消防、安责险等解决方案汇报
- 产品矩阵、技术架构、项目路线图、能力闭环展示
- OpenClaw 中需要稳定生成企业汇报 PPT 的场景

不适合：

- 需要原生 `.pptx` 动画和复杂母版编辑
- 大段密集表格、完整标书正文、培训教材逐字稿
- 追求强视觉冲击的发布会大屏或品牌广告片

## 工作流

### Step 1 · 先对齐需求

如果用户已经给了完整材料，可以直接生成初稿。材料不完整时，只问最关键的 1-3 个问题：

1. 这份 PPT 面向谁：领导汇报、客户拜访、协会会议、政府采购、内部复盘？
2. 预计页数或时长：6-8 页简版，10-15 页标准版，20 页以上深度版？
3. 是否需要配图：封面主视觉、业务场景图、架构图、生态图、产品图？

不要为了形式感追问过多问题。需求足够时先给出初稿。

### Step 2 · 建立叙事主线

生成页面前，先写一个内部使用的叙事计划。这个计划用于约束页面顺序，不需要放到最终 PPT 页面里。

```text
受众：
核心论点：
叙事弧线：
1. 背景认知 -> 这份材料为什么值得听
2. 问题张力 -> 当前缺口或机会是什么
3. 解决路径 -> 凭什么能解决
4. 能力证明 -> 资源、产品、案例、数据如何支撑
5. 行动建议 -> 接下来希望对方做什么
```

常用叙事弧线见 `references/storyline.md`。不要直接把素材目录当成 PPT 目录。

### Step 3 · 规划页面

生成前先列一张简短页面规划：

```text
页码 -> 版式 -> 这一页回答的问题 -> 本页核心结论 -> 与上一页的承接关系 -> 是否需要图片
```

规划时先做取舍：能放入演示页的是“结论、结构、关键数字、代表案例”，不是完整资料存档。长名单、长活动列表、复杂政策说明要压缩为 3-5 个重点，必要时拆页。

先判断页数模式：

- **简版 8-10 页**：适合口头快速介绍，只保留关键结论。
- **标准版 14-22 页**：适合企业汇报、年度报表、工作总结、客户提案，默认使用这个模式。
- **深度版 25 页以上**：适合标书、培训、详细复盘，需要用户明确要求。

年度报表、工作总结、项目复盘不要默认做 8 页。至少包含：

1. 封面
2. 目录
3. 章节页：背景或总体判断
4. 指标总览页
5. 结构拆解页
6. 趋势或对比页
7. 原因分析页
8. 风险/问题页
9. 章节页：重点业务或项目进展
10. 重点业务页 1
11. 重点业务页 2
12. 章节页：后续计划
13. 行动计划页
14. 结论页

常用 8 页结构只用于用户明确要求“简版”时：

1. 封面：一句话主题
2. 目录：按叙事弧线组织，而不是按素材章节罗列
3. 背景认知：为什么现在要看这个问题
4. 问题张力：现有工作缺什么、市场机会在哪里
5. 解决路径：平台或组织如何形成闭环
6. 能力证明：资源、产品、专家、案例或数据支撑
7. 推进抓手：接下来最重要的 3-4 个动作
8. 收尾：对受众的合作建议或决策请求

不要把“组织概况、核心使命、枢纽角色、工作基础、核心能力”这类平行名词直接排成目录；它们之间缺少因果和递进。改成“为什么成立 -> 解决什么缺口 -> 如何组织资源 -> 已有基础 -> 下一步怎么落地”。

### Step 4 · 拷贝模板

将模板复制到目标目录：

```powershell
New-Item -ItemType Directory -Force -Path "项目\ppt\images"
Copy-Item "<SKILL_ROOT>\assets\template-blue.html" "项目\ppt\index.html"
```

然后替换：

- `<title>` 页面标题
- `<!-- SLIDES_HERE -->` 页面内容
- 页码、标题、正文、图像路径

**生成前必须先阅读 `assets/example-full-deck.html`**，理解每页应有的内容密度、标题写法和卡片结构。不要跳过这一步。

### Step 5 · 选择版式

优先从 `references/layouts.md` 选择版式并**直接复制对应的 HTML 骨架**，在骨架上替换占位符内容。不要临时发明复杂结构。

填充内容时参考 `references/content-guide.md` 的正反对照和三要素规则。

固定版式：

- `cover`：封面
- `agenda`：目录 / 汇报结构
- `section-divider`：章节页
- `overview`：公司概况 / 业务概览
- `problem`：问题与挑战
- `solution`：整体方案
- `architecture`：技术架构
- `product-grid`：产品矩阵
- `metrics`：关键数据
- `data-dashboard`：多指标经营看板
- `chart-analysis`：图表分析
- `financial-table`：财务或经营数据表
- `comparison`：同比、竞品、方案对比
- `evidence-page`：证明材料、项目证据、案例凭据
- `roadmap`：推进路径
- `case-study`：案例或客户场景
- `risk-action`：风险与行动建议
- `closing`：收尾总结

每个页面必须写：

```html
<section class="slide" data-layout="overview" data-question="这一页回答的问题" data-message="这一页的一句话结论">
```

第一页必须使用 `cover`，并按全屏背景方式组织：

```html
<section class="slide cover-full" data-layout="cover">
```

除封面外，每页都必须有：

- `data-question`：这一页回答什么问题。
- `data-message`：这一页想让听众记住的一句话结论。

如果写不出这两个字段，说明这一页还不是一页成熟的汇报页，先重写内容。

第二页必须使用 `agenda`，不要把目录挪到后面。

### Step 6 · 配图策略

正式汇报默认至少配一张封面主视觉。以下页面建议配图：

- 封面：企业主视觉或行业场景图
- 解决方案页：业务闭环图
- 技术架构页：平台架构图
- 产品矩阵页：产品/设备/系统组合图
- 生态页：协会、保司、企业、服务机构关系图

如果需要生成图片，调用同级 `anxin-image-gen`：

```powershell
python ..\anxin-image-gen\scripts\generate_image.py `
  --prompt "中文视觉任务书" `
  --size 2048x1152 `
  --quality high `
  --output-dir ".\images"
```

配图提示词先读 `references/image-prompts.md`。提示词默认用中文，不要生成英文标题、伪中文、logo、水印、PPT 页眉页脚。

图片放入页面时：

- 封面图使用 `.cover-bg img` 并铺满页面。
- 普通正文图默认使用 `.image-contain`，确保主体完整显示；只有装饰性场景图才允许 `.image-cover`。
- 流程图、架构图、生态图必须使用 `.image-contain` 或 `object-fit: contain`。
- 图片槽位比例必须和生成尺寸一致：16:9 槽位生成 2048×1152，3:2 槽位生成 1536×1024。
- 不要把“3 张卡片 + 一张大图 + 一段长结论”上下堆在同一页；这种内容必须改成左右图文混排或拆页。
- 不要把包含大量小字的图片放到半屏以下区域；看不清就改成页面内文字结构。

### Step 7 · 自检

生成后运行：

```powershell
node "<SKILL_ROOT>\scripts\validate-blue-deck.mjs" "项目\ppt\index.html"
```

如果校验失败，必须先修复失败项，再重新运行。不要把失败项解释为“可接受问题”。

再打开浏览器人工检查：

- 目录是否能看出一条从问题到方案再到行动的逻辑链
- 每页标题是否是结论句，而不是素材标签
- 每页标题是否克制，不能像发布会海报一样压满页面
- 任意相邻两页之间是否能用一句话解释“为什么下一页接这里”
- 首页是否像企业汇报，而不是营销海报
- 页面标题是否清楚，是否全部中文优先
- 文字是否溢出、遮挡或挤压
- 图片是否真实加载，比例是否合理
- 页码、导航和底部说明是否可读
- 是否存在内容被底部导航遮挡
- 是否存在图片只显示局部、关键文字被裁掉
- 按 `Esc` 是否打开缩略图索引页，再按一次是否关闭
- 点击缩略图是否能跳转到对应页面

### Step 8 · 生成预览图

正式交付前生成关键页面截图。截图用于自检和飞书快速预览，不替代 zip。

推荐命令：

```powershell
powershell -ExecutionPolicy Bypass -File "<SKILL_ROOT>\scripts\capture-deck-screenshots.ps1" `
  -DeckDir "项目\ppt" `
  -OutputDir "项目\ppt\previews" `
  -Slides "1,2,6"
```

选择截图页：

- 第 1 页：封面是否简洁、有图。
- 第 2 页：目录是否有叙事链。
- 一页密集正文页：检查字号、溢出、遮挡和卡片密度。

### Step 9 · 打包交付

OpenClaw 通过飞书向用户交付时，不要只回复本地 `index.html` 路径。必须把整套 PPT 目录压缩成 zip，作为附件交付。

推荐命令：

```powershell
powershell -ExecutionPolicy Bypass -File "<SKILL_ROOT>\scripts\package-deck.ps1" `
  -DeckDir "项目\ppt" `
  -OutputZip "项目\安信企业汇报PPT.zip"
```

打包后确认 zip 文件真实存在，并能列出 `index.html` 和 `images/`。如果没有 zip，不算完成交付。

zip 内至少包含：

- `index.html`
- `images/`
- `previews/`，如果已经生成截图
- HTML 引用到的本地脚本、字体或其他资产

不要把 API Key、接口原始密钥、未脱敏客户资料打进 zip。

## 中文文案规则

- 默认全中文。
- 英文只保留必要专有名词，如 `AI`、`RAG`、`FLACS`、`GIS`、`BIM`、`IOT`。
- 不写无意义英文小标题，如 `BUSINESS OVERVIEW`、`VALUE PROPOSITION`。
- 不为了显得高级而中英混排。
- 页面标题优先短句，例如“高危行业安全应急平台”“从预案到实战指挥”“安责险风险减量闭环”。
- 页面标题优先写成判断句或行动句，例如“危化事故预防需要平台化协同”“安责险把事故预防变成可持续服务”。少用“组织概况”“核心能力”这类孤立标签。
- 正文页不要使用超大标题。默认模板中 `h1`、`h2`、`.lead`、`.num` 已按企业汇报收敛，生成页面时不要用内联样式把字号放大。
- 不要用空泛套话填卡片。每个卡片至少写清“对象 + 事实/数字 + 含义”，例如“能源业务收入 127.7 亿美元，同比增长 27%，是全年最明确的增长项”。
- 如果资料不足，宁可减少结论范围，也不要编造“行业领先、全面提升、显著增强”等无法验证的判断。
